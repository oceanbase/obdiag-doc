# Collect SQL details

This topic applies to scenarios where obdiag is deployed independently. You can run the obdiag gather plan_monitor command to collect execution details of the SQL statement specified by trace_id in the OceanBase cluster to which obdiag belongs. This helps you analyze the reasons for slow SQL execution at the operator level.

If the cluster is deployed by using obd, you can directly collect information about the cluster by using diagnostic commands provided by obd. For more information, see [Diagnostic commands](https://en.oceanbase.com/docs/community-obd-en-10000000000904957).

## Instructions

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This feature is supported only in OceanBase Database V3.0 and later. </p>
</main>

```shell
obdiag gather plan_monitor [options]
```

The following table describes the options.

| Option | Required? | Data type | Default value | Description |
| --- | --- | --- | --- | --- |
| --trace_id | Yes | string | Empty by default | trace_id can be obtained from `gv$sql_audit` in OceanBase Database of a version earlier than V4.0.0, and from `gv$ob_sql_audit` in OceanBase Database V4.0.0 or later. |
| --store_dir | No | string | The current path where the command is executed. | The local path where the results are stored. |
| --env | No | string | Empty by default | The connection string of the business tenant where the SQL statements related to the trace_id are located. This option is used to obtain the explain SQL report.<main id="notice" type='explain'><h4>Note</h4><p>The connection string configured cannot contain the <code>\\"'$!`</code> character. </p></main> |
| -c | No | string | `~/.obdiag/config.yml` | The path of the configuration file. |
| --inner_config | No | string | Empty by default | The configuration of obdiag. |
| --config | No | string | Empty by default | The configuration of the cluster to be diagnosed by obdiag. The format is `--config key1=value1 --config key2=value2`.  <main id="notice" type='explain'><h4>Note</h4><p>For more information about the parameters that can be configured by using this option, see <a href="../../300.obdiag-config-guide.md">Configure obdiag</a>. </p></main>     |

## Examples

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The following explains how to obtain the trace_id before use. </p>
</main>

You can obtain a trace_id from the gv$sql_audit view (when the observer version is earlier than 4.0) or from the gv$ob_sql_audit view or by executing the SELECT last_trace_id(); statement. You can choose any of the following methods:

```sql
-- Method 1: Obtain a trace_id from the sql_audit view.
select query_sql,trace_id from oceanbase.GV$OB_SQL_AUDIT where query_sql like 'xxx%' order by REQUEST_TIME desc limit 5;

-- Method 2: Execute the SELECT last_trace_id(); statement in the current session.
SELECT last_trace_id();
```

### Method 1: Use without a configuration file (out-of-the-box)

```shell
obdiag gather plan_monitor --trace_id YB420BA2D99B-0005EBBFC45D5A00-0-0 --env "{db_connect='-hxx -Pxx -uxx -pxx -Dxx'}" \
    --config db_host=xx.xx.xx.xx \
    --config db_port=xxxx \
    --config tenant_sys.user=root@sys \
    --config tenant_sys.password=***
```

The output is as follows:

```shell

Gather Summary:
+-----------+--------+-----------------------------------------------------------------------------+
| Status    | Time   | PackPath                                                                    |
+===========+========+=============================================================================+
| Completed | 6 s    | obdiag_gather_pack_20230118002457                                           |
+-----------+--------+-----------------------------------------------------------------------------+
```

### Method 2: Use with a configuration file

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Make sure that you have configured the sys connection information of the target cluster in the <code>config.yml</code> configuration file of obdiag. For more information, see <a href="../../300.obdiag-config-guide.md">Configure obdiag</a>. </p>
</main>

```shell
obdiag gather plan_monitor --trace_id YB420BA2D99B-0005EBBFC45D5A00-0-0 --env "{db_connect='-hxx -Pxx -uxx -pxx -Dxx'}"
```
