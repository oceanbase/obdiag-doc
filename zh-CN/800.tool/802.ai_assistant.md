# AI 智能诊断助手

obdiag 自 V4.0.0 起支持通过 `obdiag tool ai_assistant` 命令启动 AI 智能诊断助手。助手支持自然语言交互，可理解用户意图并调用 obdiag 的采集、分析、巡检、根因分析等能力执行诊断。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>该功能为 <strong>BETA 版本</strong>，需配置 LLM API（如 OpenAI 或兼容接口）。可选配置 MCP 以增强能力。</p>
</main>

## 功能介绍

| 能力 | 说明 |
|------|------|
| **自然语言交互** | 用自然语言描述诊断需求（如“收集最近 1 小时日志”、“检查集群健康”、“做一次根因分析”），助手会解析意图并调用对应 obdiag 命令。 |
| **内置 MCP 工具** | 默认使用 obdiag 内置 MCP 服务，将 gather/analyze/check/rca 等能力以工具形式暴露给 LLM，由 LLM 决定何时调用、传何参数。 |
| **可选外部 MCP** | 可在 `ai.yml` 中配置外部 MCP 服务，扩展更多工具或数据源。 |

## 前置配置

使用前需配置 AI 相关项，配置文件路径为 `~/.obdiag/ai.yml`。可从 `conf/ai.yml.example` 复制后修改：

```bash
# 若为源码安装，路径为 obdiag 源码根目录下的 conf/ai.yml.example
cp /opt/oceanbase-diagnostic-tool/conf/ai.yml.example ~/.obdiag/ai.yml
```

### 配置文件结构说明

`ai.yml` 分为三部分：**llm**（大模型）、**mcp**（MCP 协议）、**ui**（界面与提示）。

#### LLM 配置（必配）

用于与 OpenAI 或兼容 OpenAI 接口的服务通信，**api_key 为必填项**（也可用环境变量 `OPENAI_API_KEY`）。

```yaml
llm:
  api_type: openai                    # 类型：openai 或兼容接口
  api_key: ""                         # API Key，也可用环境变量 OPENAI_API_KEY
  base_url: ""                        # API 地址，可选；也可用环境变量 OPENAI_BASE_URL
  model: gpt-4                        # 模型名，如 gpt-4、gpt-3.5-turbo、qwen-plus 等
  temperature: 0.7                    # 随机度 0–2，越小越稳定
  max_tokens: 2000                    # 单次回复最大 token 数
  system_prompt: ""                   # 可选，自定义系统提示词；空则使用内置
```

**base_url 示例**：

- OpenAI 官方：<https://api.openai.com/v1>
- Azure OpenAI：<https://your-resource.openai.azure.com/openai/deployments/your-deployment>
- 自定义：<https://your-api-server.com/v1>

#### MCP 配置（可选）

默认启用内置 MCP 服务，无需额外配置即可使用 obdiag 的 gather/analyze/check/rca 等工具。仅在使用**外部 MCP 服务**时需要配置 `mcp.servers`。

```yaml
mcp:
  enabled: true                      # 是否启用 MCP 工具
  servers: ""                        # 外部 MCP 服务，空则仅用内置
  # 若使用外部服务，可为 JSON 字符串，格式兼容 mcp.json，例如：
  # servers: |
  #   {
  #     "my_server": {
  #       "command": "some-mcp-command",
  #       "args": ["stdio"]
  #     },
  #     "http_server": {
  #       "url": "http://127.0.0.1:8000/mcp"
  #     }
  #   }
```

**内置 MCP 工具示例**：gather_log、gather_sysstat、gather_perf、gather_obproxy_log、gather_ash、gather_awr、analyze_log、check、check_list、rca_run、rca_list、tool_io_performance 等。交互模式下输入 `tools` 可查看当前加载的工具列表。

#### UI 配置（可选）

```yaml
ui:
  show_welcome: true                 # 启动时是否显示欢迎信息
  show_beta_warning: true            # 是否显示 BETA 提示
  clear_screen: true                 # 进入交互前是否清屏
  prompt: "obdiag AI> "              # 输入行前缀
```

## 注意事项

- **BETA 功能**：界面与行为可能随版本调整，遇到问题可到 [GitHub Issues](https://github.com/oceanbase/obdiag/issues) 反馈。
- **API 费用**：调用外部 LLM 会产生费用，请自行控制用量。
- **敏感信息**：obdiag 不会把集群密码等敏感信息发给 LLM；仅会按需传入执行 obdiag 子命令所需的参数。
- **网络与权限**：执行 gather/check/rca 等时依赖 `-c` 指定的集群配置与当前机器到集群的 SSH/网络可达性，与直接执行 obdiag 子命令要求一致。

## 命令说明

```shell
obdiag tool ai_assistant [options]
```

| 选项名 | 是否必选 | 数据类型 | 默认值 | 说明 |
|--------|----------|----------|--------|------|
| -c | 否 | string | `~/.obdiag/config.yml` | obdiag 集群配置文件路径；AI 助手调用 gather/check/rca 等时会使用该配置连接集群。 |
| --config_password | 否 | string | 默认为空 | obdiag 使用加密的配置文件时，需通过该选项传入对应的密码。详见 [配置文件加密](801.crypto_config.md)。 |
| -h/--help | 否 | - | - | 无需传值，命令中配置即表示查看命令帮助。 |
| -v/--verbose | 否 | - | - | 无需传值，命令中配置即表示输出详细日志。 |

### 交互模式下的命令

启动后进入交互模式，除自然语言提问外，还支持以下指令：

| 指令 | 说明 |
|------|------|
| `help`/`?` | 显示帮助与示例问法。 |
| `exit`/`quit`/`q` | 退出 AI 助手。 |
| `clear` | 清空当前会话的对话历史（不影响已执行的 obdiag 命令）。 |
| `history` | 查看当前会话的对话历史。 |
| `tools` | 列出当前可用的诊断工具（内置 MCP 及已连接的外部 MCP 工具）。 |

## 使用示例

### 启动 AI 助手

```shell
obdiag tool ai_assistant
```

若使用自定义集群配置或加密配置，示例如下：

```shell
obdiag tool ai_assistant -c /path/to/config.yml
obdiag tool ai_assistant -c ~/.obdiag/config.yml.encrypted --config_password=your_secret
```

## 常见问题

- **报错：OpenAI API key is required**  
  请在 `~/.obdiag/ai.yml` 的 `llm.api_key` 中配置 Key，或设置环境变量 `OPENAI_API_KEY`。

- **如何只用内置能力、不连外网？**  
  配置 `llm` 为可访问的兼容 OpenAI 的内网或本地模型服务（`base_url` + `api_key`），并保持 `mcp.servers` 为空即可使用内置 MCP 工具。

- **如何查看本次会话用到了哪些工具？**  
  在交互中输入 `tools` 可查看已加载工具列表及 MCP 连接状态；执行过程中若开启 `-v`，会输出更详细的调用日志。
