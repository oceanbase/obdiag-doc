# 根因分析场景：事务执行超时报错 transaction_execute_timeout

## 适用场景

本文适用于针对事务执行超时报错的根因分析，基于 OceanBase 数据库内部表数据以及日志进行分析。

目前支持 OceanBase 数据库 V4.0.0.0 及之后的版本。使用 obdiag 时需根据选择在 `~/.obdiag/config.yml` 文件中配置集群信息，或在命令中通过 `--config` 选项配置集群信息。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>由于内部数据存在及时性，所以仅支持对当前时的数据进行分析。</p>
</main>

## 可导入环境变量

| 变量名       | 是否必选 | 数据类型   | 默认值 | 说明                                                        |
|-----------|------|--------|-----|-----------------------------------------------------------|
| tenant_id | 是    | string | ""  | 租户 ID                                                      |
| trace_id  | 是    | string | ""  | trace_id                                                  |
| err_type  | 是    | string | ""  | 错误类型，可选为 `statement is timeout` 或 `transaction is timeout` |

## 使用示例

配置分析场景，并指定租户、trace_id 等相关信息的执行示例如下：

```shell
obdiag rca run --scene=transaction_execute_timeout --input_parameters='{"tenant_id":"1002","trace_id":"YXXXXXXXXXX","err_type":"statement is timeout"}'
```
