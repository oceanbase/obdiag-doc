# 根因分析场景：执行 DDL 报错磁盘满 ddl_disk_full

## 适用场景

本文适用于对于 DDL 报错磁盘满的场景，基于 OceanBase 数据库不同版本写入放大系数以及源表大小分析出各个节点的剩余空间是否充足。

目前支持 OceanBase 数据库 V4.0.0.0 及之后的版本。使用 obdiag 时需根据选择在 `~/.obdiag/config.yml` 文件中配置集群信息，或在命令中通过 `--config` 选项配置集群信息。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <ul><li>
  <p>由于内部数据存在及时性，所以仅支持对当前时的数据进行分析。</p>
  </li><li>
  <p>OceanBase 数据库 V4.2.3.0 之前版本与之后版本的写入放大系数存在不同，V4.2.3.0 之前放大系数为 5.5，V4.2.3.0 及之后的放大系数为 1.5。</p>
  </li></ul>
</main>

## 可导入环境变量

| 变量名           | 是否必选 | 数据类型   | 默认值       | 说明              |
|---------------|------|--------|-----------|-----------------|
| table_name    | 是    | string | ""        | 表名              |
| tenant_name   | 是    | string | 10        | 租户名             |
| action_type   | 否    | string | add_index | 行为类别，目前仅支持加索引场景 |
| index_name    | 是    | string | ""        | 索引名称            |
| database_name | 是    | string | ""        | 数据库名            |

## 使用示例

指定环境变量执行示例如下：

```shell
 obdiag rca run --scene=ddl_disk_full --env tenant_name=test1 --env table_name=t555 --env action_type=add_index --env index_name=k1 --env database_name=xxxx
```
