# 根因分析场景：执行 ddl 报错磁盘满 ddl_disk_full

## 适用场景
本文适用于对于 ddl 报错磁盘满的场景，基于 observer 不同版本写入放大系数以及源表大小分析出各个节点的剩余空间是否充足。

目前支持 observer 4.0.0.0及之后的版本。 

obdiag 使用前需要配置 ~/.obdiag/config.yml 或使用 --config 配置集群信息。

由于内部数据存在及时性，所以仅支持对当前时的数据进行分析。

注意：4.2.3.0版本之前与之后的版本的写入放大系数存在不同，4.2.3.0之前放大系数为5.5，之后的放大系数为1.5.


## 可导入环境变量

| 变量名         | 是否必选 | 数据类型   | 默认值       | 说明              |
|-------------|------|--------|-----------|-----------------|
| table_name  | 是    | string | ""        | 表名              |
| tenant_name | 是    | string | 10        | 最大分析异常场景的数量     |
| action_type | 否    | string | add_index | 行为类别，目前仅支持加索引场景 |
| index_name  | 是    | string | “”        | 索引名称            |


## 使用示例

### 1. 指定环境变量执行

```shell
obdiag rca run --scene=ddl_disk_full --input_parameters='{"tenant_name":"test1","table_name":"t555","action_type":"add_index","index_name":"k1"}'
```
