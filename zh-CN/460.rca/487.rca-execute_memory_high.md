# 根因分析场景：SQL 执行内存过高 execute_memory_high

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>obdiag 自 V4.2.0 起支持对 SQL 执行内存过高的场景进行根因分析。</p>
</main>

## 适用场景

本文适用于 SQL 执行过程中工作区内存（work area memory）占用过高的场景，基于 OceanBase 数据库内部表及视图进行分析，定位执行内存消耗原因。

目前支持 OceanBase 数据库 V4.0.0.0 及之后的版本。使用 obdiag 时需根据选择在 `~/.obdiag/config.yml` 文件中配置集群信息，或在命令中通过 `--config` 选项配置集群信息。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>由于内部数据存在及时性，所以仅支持对当前时的数据进行分析。</p>
</main>

## 分析内容

该场景会检查以下内容：

1. **执行内存使用**：从 `__all_virtual_memory_info` 获取 SQL 执行内存使用情况。
2. **GV$OB_SQL_WORKAREA_MEMORY_INFO**：若 OceanBase 数据库版本支持（V4.3 及以上版本），查询工作区内存详情。
3. **GV$SQL_WORKAREA**：若 OceanBase 数据库版本支持（V2.2.77 及以上版本），查询活跃工作区信息。
4. **内存参数**：`ob_sql_work_area_percentage` 及相关参数。
5. **Top 消耗**：内存消耗最高的 SQL 及模块。
6. **日志收集**：收集 OceanBase 数据库日志便于进一步分析。

## 使用示例

默认执行命令如下：

```shell
obdiag rca run --scene=execute_memory_high
```

## 结果解读

分析完成后，结果会保存至 `--store_dir` 指定目录（默认为 `./obdiag_rca/`），包含各检查步骤的记录及收集的日志文件。
