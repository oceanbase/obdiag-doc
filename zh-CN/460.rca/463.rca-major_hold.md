# 根因分析场景：卡合并 major_hold

## 适用场景

本文适用于对于卡合并的场景，基于 OceanBase 数据库内部日志及内部表数据分析定位到问题所在。

目前支持 OceanBase 数据库 V4.0.0.0 及之后的版本。使用 obdiag 时需根据选择在 `~/.obdiag/config.yml` 文件中配置集群信息，或在命令中通过 `--config` 选项配置集群信息。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>由于内部表数据存在及时性，所以仅支持对当前时的数据进行分析。</p>
</main>

## 使用示例

默认执行命令如下，仅分析当前情况下卡合并的原因。

```shell
obdiag rca run --scene=major_hold 
```

目前阶段卡合并场景主要用于初步的分析定位及有效信息收集，需要在完成后将收集的有效信息进行打包并上传社区 [问答区](https://ask.oceanbase.com/) 或 OceanBase 运维进行进一步分析。

## 分析内容

自 obdiag V4.0.0 起，该场景增强了以下分析能力：

1. **重复索引名检测**：检查是否存在重复的索引名导致合并卡住。
2. **DDL 任务状态检查**：分析当前 DDL 任务的执行状态，判断是否因 DDL 任务阻塞导致合并卡住。
3. **日志分析增强**：分析 OceanBase 集群日志中更多与合并相关的错误信息。

自 obdiag V4.1.0 起，该场景进一步增强了以下分析能力：

1. **内存节流检查**：检查租户内存使用情况和内存节流状态，识别因内存不足导致的合并失败问题。包括：
   - 租户内存使用率检查
   - MemStore 使用率与写入节流触发阈值检查
   - TxShare 节流限制检查
   - 与节流相关的事务超时问题检查
2. **Dump/Merge/Freeze 信息查询**：当诊断信息显示 `medium wait for freeze` 或 `major wait for freeze` 时，会查询并保存以下信息：
   - DAG 调度器冻结信息（`dag_scheduler_freeze.json`）
   - Minor Freeze 信息（`minor_freeze_info.json`，从 `__all_virtual_minor_freeze_info` 视图获取）
   - 提供合并等待冻结的可能原因和建议

自 obdiag V4.2.0 起，该场景新增以下分析能力：

1. **列组 Schema 问题检查**：检测异构行列转换场景下 `__all_virtual_column_group_history` 中的旧 `__co_all` 记录，查询 `__all_virtual_sys_task_status` 中的 SSTABLE_MAJOR_MERGE 任务，并提供处理步骤。
