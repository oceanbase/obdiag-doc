# 根因分析场景：锁冲突 lock_conflict

## 适用场景
本文适用于对于锁冲突的场景，基于 observer 内部表数据分析定位到持锁会话及等锁会话所在。

目前支持 observer 4.0.0.0及之后的版本。 

obdiag 使用前需要配置 ~/.obdiag/config.yml 或使用 --config 配置集群信息。

由于内部表数据存在及时性，所以仅支持对当前时的数据进行分析。

注意：4.2.0.0之前与之后的版本分析逻辑存在差异。

## 使用示例

### 1. 默认执行：当前情况下基于 observer 内部表数据分析定位到持锁会话及等锁会话所在。

```shell
obdiag rca run --scene=lock_conflict 
```
 
鉴于未开启事务的时候等锁id会由于不断变化，在 obdiag rca的锁冲突策略中， record 中的分析为持锁的session（与ocp表现相同），同时会打印查询时期的信息，并进行标注是持锁的id。等锁session信息若查询得到会进行记录，但是不作为关键节点进行说明。
