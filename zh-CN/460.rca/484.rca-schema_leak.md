# 根因分析场景：Schema 泄漏 schema_leak

## 适用场景

本文适用于针对 Schema 泄漏问题的根因分析，基于 OceanBase 数据库内部表数据以及日志进行分析，帮助定位 Schema 泄漏的原因。

目前支持 OceanBase 数据库 V4.0.0.0 及之后的版本。使用 obdiag 时需根据选择在 `~/.obdiag/config.yml` 文件中配置集群信息，或在命令中通过 `--config` 选项配置集群信息。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>由于内部表数据存在及时性，所以仅支持对当前时的数据进行分析。</p>
</main>

## 可导入环境变量

| 变量名   | 是否必选 | 数据类型   | 默认值   | 说明        |
|-------|------|--------|-------|-----------|
| tenant_id | 否    | string | ""  | 指定待分析的租户 ID。 |

## 使用示例

* 配置分析场景，默认执行

  ```shell
  obdiag rca run --scene=schema_leak
  ```

* 配置分析场景，并指定租户 ID

  ```shell
  obdiag rca run --scene=schema_leak --env tenant_id=1001
  ```

## 分析内容

该场景会分析以下内容：

1. **Schema 版本历史**：检查 Schema 版本的历史记录，分析是否存在异常增长。
2. **Schema 刷新状态**：分析 Schema 刷新的状态和频率。
3. **内存占用分析**：检查 Schema 相关的内存占用情况。
4. **历史 DDL 操作**：分析历史 DDL 操作是否导致 Schema 泄漏。

## 输出结果

分析完成后会生成诊断报告，报告中包含：

* Schema 泄漏的根因分析结果
* 泄漏点定位信息
* 修复建议

## 常见原因

Schema 泄漏的常见原因包括：

* 频繁的 DDL 操作导致 Schema 版本过多。
* Schema 刷新机制异常。
* 长时间运行的事务阻止 Schema 回收。
* 某些 Bug 导致的 Schema 无法正常清理。

## 解决建议

* 避免过于频繁的 DDL 操作。
* 检查是否存在长时间运行的事务或会话。
* 如确认为 Bug，请升级到修复版本或联系技术支持。
