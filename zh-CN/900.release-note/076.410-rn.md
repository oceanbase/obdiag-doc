# obdiag V4.1.0

## 版本信息

- 发布时间：2026 年 02 月 12 日
- 版本号：V4.1.0

## 新版本变更功能点

### 新增命令与场景

- 【新增】`obdiag display scene run` 命令新增 CLOG 日志量/容量统计场景（`observer.clog_volume_statistics`），支持展示各节点/租户 CLOG 日志盘容量与使用情况。场景使用方式参见 [一键集群洞察场景](../470.display/601.obdiag-display-scene-guide.md)。

- 【新增】`obdiag display-trace <trace_id>` 命令，用于查看单次 obdiag 执行的详细日志，便于排查命令执行问题。执行部分命令后终端会提示可用的 trace_id。

### 功能增强

- 【新增】`obdiag gather perf` 命令支持生成火焰图 SVG，便于分析 CPU 热点。需在 `dependencies/bin` 下提供 `flamegraph.pl` 与 `stackcollapse-perf.pl`。具体介绍可参见 [Perf 与火焰图收集](../400.gather/100.normal/105.gather_perf.md)。

- 【新增】`obdiag analyze log` 命令新增 `--tenant_id` 选项，支持按租户过滤错误统计；分析逻辑重构，支持先收集压缩包再本地解压分析，提升大日志分析效率。具体介绍可参见 [日志分析](../450.analyze/501.analyze_log.md)。

- 【新增】`obdiag analyze flt_trace` 支持按客户端 IP 过滤 OBProxy 节点，并从 SQL 审计视图获取 client IP，兼容多版本 OceanBase。具体介绍可参见 [FLT Trace 分析](../450.analyze/502.analyze_flt_trace.md)。

- 【新增】`obdiag gather plan_monitor` 生成的报告中增加统计信息直方图（表级/分区级），便于分析执行计划与统计信息。具体介绍可参见 [执行计划监控收集](../400.gather/100.normal/109.gather_plan_monitor.md)。

- 【优化】卡合并 RCA 场景（`obdiag rca run --scene=major_hold`）增加内存节流检查及 dump/merge/freeze 相关信息查询，便于定位合并卡住原因。具体介绍可参见 [根因分析场景：卡合并](../460.rca/463.rca-major_hold.md)。

- 【变更】检查框架由 `checker` 重构为 `check`，采用 TaskBase 与 Python 巡检任务体系；大量巡检任务由 YAML 迁移为 Python 实现，行为与 V4.0.0 保持一致，并支持通过 `obdiag check run` 的 `--observer_tasks`/`--obproxy_tasks` 等选项灵活执行。具体介绍可参见 [一键集群巡检](../360.cluster-monitor/370.use-obiag-check-patrol-oceanbase-database-cluster.md)。

### 安装与构建

- 【说明】V4.1.0 持续使用 `pyproject.toml` 管理依赖与构建，详见 [安装与部署](../200.install-and-deploy-obdiag.md)。
