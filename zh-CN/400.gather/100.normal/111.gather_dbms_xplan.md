# DBMS_XPLAN 信息收集

本文适用于独立部署 obdiag 的场景，使用 `obdiag gather dbms_xplan` 命令可以一键使用 DBMS_XPLAN 系统包收集 SQL 的性能诊断信息。

如果是 obd 部署的集群，可直接通过 obd 侧诊断命令组对所选集群进行信息收集，详细命令可参考 [诊断工具命令组](https://www.oceanbase.com/docs/community-obd-cn-1000000002884636)。

## 使用说明

```shell
obdiag gather dbms_xplan [options]
```

选项说明如下：

| 选项名           | 是否必选 | 数据类型   | 默认值                     | 说明                                                                                        |
|---------------|------|--------|-------------------------|-------------------------------------------------------------------------------------------|
| --trace_id   | 是    | string |   默认为空              | OceanBase 数据库 V4.0.0 以下版本可从 `gv$sql_audit` 中查看 trace_id，OceanBase 数据库 V4.0.0 及以上版本可从 `gv$ob_sql_audit` 中查看 trace_id。  |
| --scope        | 否    | string | all                     | 选择收集 SQL 的性能诊断信息时所用的 DBMS_XPLAN 系统包，可配置值如下：<ul><li><code>opt_trace</code>：使用 DBMS_XPLAN.ENABLE_OPT_TRACE 函数收集 SQL 的性能诊断信息。 </li><li><code>display_cursor</code>：使用 DBMS_XPLAN.DISPLAY_CURSOR 函数收集 SQL 的性能诊断信息。</li><li><code>all</code>：使用 DBMS_XPLAN.ENABLE_OPT_TRACE 和 DBMS_XPLAN.DISPLAY_CURSOR 函数收集 SQL 的性能诊断信息。</li></ul>                           |
| --user  | 是    | string | 默认为空                    | 待收集 SQL 的所在租户的用户名。 |
| --password  | 是    | string | 默认为空                    | 待收集 SQL 所在租户的用户密码。 |
| --store_dir   | 否    | string | 默认为命令执行的当前路径            | 存储结果的本地路径。                                                                                |
| -c            | 否    | string | `~/.obdiag/config.yml` | 配置文件路径。                                                                                    |
| --inner_config | 否    | string |   默认为空           | obdiag 自用的配置。     |
| --config | 否    | string |   默认为空           | 需被 obdiag 诊断的集群的配置，固定样式：`--config key1=value1 --config key2=value2`。  <main id="notice" type='explain'><h4>说明</h4><p>支持通过该选项配置的参数可参见 <a href="../../300.obdiag-config-guide.md">obdiag 配置</a>。</p></main>    |

## 使用示例

### 方式一：无配置文件使用（开箱即用）

```shell
obdiag gather dbms_xplan --user=<MYUSER> --password=<MYPASSWORD> --password=<MYPASSWORD> --trace_id=<TRACE_ID> \
    --config db_host=xx.xx.xx.xx \
    --config db_port=xxxx \
    --config tenant_sys.user=root@sys \
    --config tenant_sys.password=***
```

输出如下：

```shell
$ obdiag gather dbms_xplan --user xxxx --password *** --trace_id YF2A0BA2DA7E-0006350FB4EBBD8A-0-0 \
    --config db_host=xx.xx.xx.xx \
    --config db_port=xxxx \
    --config tenant_sys.user=root@sys \
    --config tenant_sys.password=***

gather_dbms_xplan start ...
execute dbms_xplan.enable_opt_trace start ...
SET TRANSACTION ISOLATION LEVEL READ COMMITTED
call dbms_xplan.enable_opt_trace();
call dbms_xplan.set_opt_trace_parameter(identifier=>'obdiag_MkaDL7', `level`=>3);
call dbms_xplan.disable_opt_trace();
execute dbms_xplan.enable_opt_trace end
```

### 方式二：有配置文件使用

需要确保已经在 obdiag 配置文件 <code>config.yml</code> 中配置好需要收集节点的登录信息。相关的详细配置介绍，参见 [obdiag 配置](../../300.obdiag-config-guide.md)。

```shell
obdiag gather dbms_xplan --user=<MYUSER> --password=<MYPASSWORD> --trace_id=<TRACE_ID>
```

## 结果解读

命令执行后在指定目录下会生成一个结果文件夹，文件夹形如: `./obdiag_gather_pack_xxxxx`。

```bash
$tree
.
├── xx_xx_xx_xx_optimizer_trace_G6WfT1_obdiag_MkaDL7.trac # 通过 dbms_xplan.enable_opt_trace 收集到的文件
└── obdiag_dbms_xplan_display_cursor.txt # 通过 dbms_xplan.display_cursor 收集到的文件
```

详细的结果解读参加：[诊断实践：使用 DBMS_XPLAN 系统包进行性能诊断](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002012866)。
