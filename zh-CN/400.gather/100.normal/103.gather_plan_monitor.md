# SQL 详情收集

本文适用于独立部署 obdiag 的场景，使用 obdiag gather plan_monitor 命令可以一键收集所属 OceanBase 集群指定 trace_id 的 SQL 的执行详情信息，便于 分析SQL 执行慢时分析算子层面的原因。

如果是 obd 部署的集群，可直接通过 obd 侧诊断命令组对所选集群进行信息收集，详细命令可参考 [诊断工具命令组](https://www.oceanbase.com/docs/community-obd-cn-10000000002049483)。

## 使用说明

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>该功能仅支持 OceanBase 数据库 V3.0 及以上版本。</p>
</main>

```shell
obdiag gather plan_monitor [options]
```

选项说明如下：

| 选项名                 | 是否必选 | 数据类型   | 默认值                       | 说明                                                                |
|---------------------|------|--------|---------------------------|-------------------------------------------------------------------|
| --trace_id   | 是    | string |   默认为空              | OceanBase 数据库 V4.0.0 以下版本可从 `gv$sql_audit` 中查看 trace_id，OceanBase 数据库 V4.0.0 及以上版本可从 `gv$ob_sql_audit` 中查看 trace_id。  |
| --store_dir   | 否    | string |   默认为命令执行的当前路径              | 存储结果的本地路径。 |
| --env   | 否    | string |   默认为空              | 要分析的 trace_id 涉及的 SQL 所在业务租户的连接串，主要用于获取 explain SQL 报告。<main id="notice" type='explain'><h4>说明</h4><p>暂不支持配置的连接串中包含 <code>\\"'$!`</code> 字符。</p></main> |
| -c | 否    | string |   `~/.obdiag/config.yml`           | 配置文件路径。     |
| --inner_config | 否    | string |   默认为空           | obdiag 自用的配置。     |
| --config | 否    | string |   默认为空           | 需被 obdiag 诊断的集群的配置，固定样式：`--config key1=value1 --config key2=value2`。  <main id="notice" type='explain'><h4>说明</h4><p>支持通过该选项配置的参数可参见 <a href="../../300.obdiag-config-guide.md">obdiag 配置</a>。</p></main>     |

## 使用示例

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>使用前获取 trace_id 的方法如下</p>
</main>

从 gv$ob_sql_audit(observer 版本小于4.0时为 gv$sql_audit) 中获取或者通过SELECT last_trace_id();获取，以下两种方式任选一种

```sql
-- 方法一：通过sql_audit中获取
select query_sql,trace_id from oceanbase.GV$OB_SQL_AUDIT where query_sql like 'xxx%' order by REQUEST_TIME desc limit 5;

-- 方法二：通过当前session执行SELECT last_trace_id();获取
SELECT last_trace_id();
```

### 方式一：无配置文件使用（开箱即用）

```shell
obdiag gather plan_monitor --trace_id YB420BA2D99B-0005EBBFC45D5A00-0-0 --env "{db_connect='-hxx -Pxx -uxx -pxx -Dxx'}" \
    --config db_host=xx.xx.xx.xx \
    --config db_port=xxxx \
    --config tenant_sys.user=root@sys \
    --config tenant_sys.password=***
```

输出如下：

```shell

Gather Summary:
+-----------+--------+-----------------------------------------------------------------------------+
| Status    | Time   | PackPath                                                                    |
+===========+========+=============================================================================+
| Completed | 6 s    | obdiag_gather_pack_20230118002457                                           |
+-----------+--------+-----------------------------------------------------------------------------+
```

### 方式二：有配置文件使用

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>需要确保已经在 obdiag 配置文件 <code>config.yml</code> 中配置好需要收集的集群 sys 连接信息。相关的详细配置介绍，参见 <a href="../../300.obdiag-config-guide.md">obdiag 配置</a>。</p>
</main>

```shell
obdiag gather plan_monitor --trace_id YB420BA2D99B-0005EBBFC45D5A00-0-0 --env "{db_connect='-hxx -Pxx -uxx -pxx -Dxx'}"
```
