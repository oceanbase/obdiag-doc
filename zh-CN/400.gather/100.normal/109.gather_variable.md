## 变量收集

本文适用于独立部署 obdiag 的场景，使用 obdiag gather variable 命令可以一键收集变量信息，并存放成 csv 文件，可用于变量比对存档

如果是 obd 部署的集群，可直接通过 obd 侧诊断命令组对所选集群进行信息收集，详细命令可参考 [诊断工具命令组](https://www.oceanbase.com/docs/community-obd-cn-10000000002049483)。

## 使用说明

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>需要确保已经在 obdiag 配置文件 <code>config.yml</code> 中配置好需要收集节点的登录信息。相关的详细配置介绍，参见 <a href="../300.obdiag-config-guide.md">obdiag 配置</a>。</p>
</main>

```shell
obdiag gather variable [options]
```

选项说明如下：

| 选项名           | 是否必选 | 数据类型   | 默认值                     | 说明                                                                                        |
|---------------|------|--------|-------------------------|-------------------------------------------------------------------------------------------|
| --store_dir   | 否    | string | 默认为命令执行的当前路径            | 存储结果的本地路径。                                                                                |
| -c            | 否    | string | `~/.obdiag/config.yml ` | 配置文件路径                                                                                    |


# 使用示例

```shell

obdiag gather variable

gather_variables start ...
Gather variables finished. For more details, please run cmd 'cat /home/admin/gather_variables/gather_variables/obcluster_variables_20240808144053.csv'
Trace ID: 28736940-5551-11ef-9ca9-a6e6206c49dc
If you want to view detailed obdiag logs, please run: obdiag display-trace 28736940-5551-11ef-9ca9-a6e6206c49dc

```

```shell
# 通过 --store_dir 参数指定收集结果存储到 /tmp 目录下
obdiag gather variable --store_dir /tmp/

# 通过 -c 指定被收集的集群配置
obdiag gather variable --store_dir -c test.yml

```


## 报告解读

- 命令执行后在指定目录下会生成一个 csv 文件，文件形如: ./gather_variables/obcluster_variables_20240808144053.csv, 可用于变量比对存档
