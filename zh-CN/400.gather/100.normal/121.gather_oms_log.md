# OMS 日志收集

本文适用于独立部署 obdiag 的场景，使用 `obdiag gather oms_log` 命令可一键收集 OceanBase 迁移服务（OMS）相关组件的日志。

若是 OBD 部署的集群，可直接通过 OBD 侧诊断命令组进行信息收集，详见 [诊断工具命令组](https://www.oceanbase.com/docs/common-obd-cn-1000000004376513)。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>使用前需在 obdiag 配置中填写 OMS 相关节点的 SSH 登录信息（即配置中需包含 OMS 节点的 IP、ssh_username、ssh_password、home_path 等）。OMS 节点配置方式与 obcluster/obproxy 类似，具体可参考部署文档或联系管理员获取。</p>
</main>

## 使用说明

```shell
obdiag gather oms_log [options]
```

选项说明如下：

| 选项名 | 是否必选 | 数据类型 | 默认值 | 说明 |
|--------|----------|----------|--------|------|
| --from | 否 | string | 默认为空 | 日志收集的开始时间，格式：`yyyy-mm-dd hh:mm:ss`。 |
| --to | 否 | string | 默认为空 | 日志收集的结束时间，格式：`yyyy-mm-dd hh:mm:ss`。 |
| --since | 否 | string | `30m` | 相对当前时间的时间范围，格式：`<n><m\|h\|d>`，如 `1h` 表示最近 1 小时。 |
| --scope | 否 | string | all | 要收集的 OMS 日志类型。可选：`console`、`nginx`、`supervisord`、`drc`、`ghana`、`scheduler`、`web`、`alarm`、`api`、`gc`、`cm`、`supervisor`、`cdc`、`libobcdc`、`store`、`all`。 |
| --grep | 否 | string | 默认为空 | 关键字过滤，可多次指定，仅收集包含指定关键字的日志行。 |
| --store_dir | 否 | string | 当前目录 | 存储结果的本地路径。 |
| --temp_dir | 否 | string | `/tmp` | 远端 OMS 节点上临时文件存放目录。 |
| --recent_count | 否 | int | 0 | 仅收集最近 N 个日志文件；大于 0 时忽略 `--from`、`--to`、`--since`。 |
| --oms_component_id | 否 | string | 默认为空 | CDC 日志对应的 OMS 组件 ID，格式：`x.x.x.x-123`。 |
| -c | 否 | string | `~/.obdiag/config.yml` | 配置文件路径。 |
| --inner_config | 否 | string | 默认为空 | obdiag 自用配置，格式：`--inner_config key=value`。 |
| --config | 否 | string | 默认为空 | 集群/OMS 节点配置，格式：`--config key1=value1 --config key2=value2`。详见 [obdiag 配置](../../300.obdiag-config-guide.md)。 |
| --config_password | 否 | string | 默认为空 | 使用加密配置文件时的密码。详见 [配置文件加密](../../800.tool/801.crypto_config.md)。 |

## 前提条件

1. 已安装 obdiag，并完成用户侧配置。
2. 配置中已包含 OMS 节点的 SSH 登录信息及 **log_path**（OMS 日志根目录），确保 obdiag 所在机器能 SSH 到 OMS 节点。

## 使用示例

### 方式一：有配置文件使用

确保 `~/.obdiag/config.yml` 中已配置 OMS 节点信息后，执行：

```shell
# 收集最近 30 分钟的 OMS 日志（默认）
obdiag gather oms_log

# 收集最近 1 小时的 OMS 日志
obdiag gather oms_log --since 1h

# 指定时间范围
obdiag gather oms_log --from "2024-01-15 10:00:00" --to "2024-01-15 11:00:00"

# 仅收集 console 与 cdc 类型日志
obdiag gather oms_log --scope console --scope cdc

# 关键字过滤
obdiag gather oms_log --since 1h --grep "ERROR" --grep "Exception"

# 仅收集最近 5 个日志文件
obdiag gather oms_log --recent_count 5

# 指定 CDC 组件 ID（采集 CDC 相关日志时）
obdiag gather oms_log --since 1h --oms_component_id 192.168.1.10-12345 --scope cdc
```

### 方式二：通过 --config 传递配置（开箱即用）

通过 `--config` 传递 OMS 节点信息时，需指定各 OMS 节点的 IP、ssh 登录信息及 **log_path**（OMS 日志根目录），例如：

```shell
obdiag gather oms_log --since 1h \
    --config oms.servers.nodes[0].ip=xx.xx.xx.1 \
    --config oms.servers.nodes[1].ip=xx.xx.xx.2 \
    --config oms.servers.global.ssh_username=admin \
    --config oms.servers.global.ssh_password=****** \
    --config oms.servers.global.log_path=/home/admin/logs
```

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p>OMS 采集依赖配置中的 <code>oms.servers</code> 及 <code>oms.servers.global.log_path</code>（OMS 日志根目录，必填）。CDC 相关日志还需配置 <code>store_path</code>，并在命令中指定 <code>--oms_component_id</code>。配置模板可参考 <code>~/.obdiag/example/all-components-with-oms.yml</code>。</p>
</main>

## 结果说明

命令执行成功后，会在 `--store_dir` 指定的目录下生成采集包（如 `obdiag_gather_pack_yyyyMMddHHmmss`），内含各 OMS 节点按时间与 scope 收集的日志压缩包，便于迁移与同步问题的排查。
